# Spec — Branded DMG installer background artwork

**Date:** 2026-08-10
**Issue:** #741
**Status:** Approved (design confirmed from rendered mockups, 2026-08-10)

## Goal

Replace the default, blank `create-dmg` layout for the OnlyCue installer window with a **designed, dark, on-brand background** — so mounting the `.dmg` feels like an extension of the app, not a generic drag-install window (the way Figma's installer does, but in OnlyCue's dark identity with OnlyCue's own icon and motifs).

## Background / problem

`scripts/make-dmg.sh` currently calls `create-dmg` with only a window size, icon size, the app-icon position, and the Applications drop-link — no `--background`. The result is a plain white Finder window. We want branded artwork around the two live icons.

The app icon (`OnlyCue/Resources/Assets.xcassets/AppIcon.appiconset/`) is a dark rounded square with a **vertical-bar waveform** and a **cue marker = a thin indigo vertical line topped by a round dot** (a playhead), plus "ONLY CUE". It is generated by a committed CoreGraphics script, `scripts/generate-app-icon.swift` — the repo convention for branded raster art.

## Key facts that shaped the design

- The DMG background image is drawn by Finder as the window backdrop; Finder draws the **live icons on top** — the `.app` (which already *is* OnlyCue's icon), the **Applications** folder symlink, their **text labels**, and the **window title bar** (the volume name, e.g. `OnlyCue 0.23.0`). Therefore the background art must contain **everything except those** — do NOT bake the icon, folder, labels, or title bar into the background.
- The repo already generates branded art via a standalone `#!/usr/bin/env swift` CoreGraphics script whose output PNG is committed. We follow that pattern.
- A release build must not depend on regenerating art, so the generated PNGs are committed (like the app-icon PNGs).

## Design (approved)

Dark, on-brand, restrained, engineering-feel. Window content **600 × 400** (up from the current 540 × 380, for breathing room).

**Background art layers (bottom → top):**

1. **Brand dark gradient** — linear, top-left `rgb(0.16, 0.18, 0.24)` → bottom-right `rgb(0.04, 0.06, 0.10)` (the same gradient as `generate-app-icon.swift`, for cohesion).
2. **Cool-white icon glow** — a soft radial glow `rgb(0.75, 0.80, 0.95)` fading `0.16 → 0` alpha over ~120 px radius, centered on the app-icon anchor, so the icon reads as gently lit.
3. **"Like a real song" waveform** — a centered strip of fine **vertical bars** (mirrored about a baseline, matching the icon's waveform), achromatic grey `rgb(0.74, 0.72, 0.66)` @ ~0.34 alpha. Heights are **deterministically pseudo-random** (see below): macro "loud/quiet sections" over per-bar randomness with occasional transient spikes, gently faded at the strip ends. Deterministic so the committed script reproduces byte-identical art every run.
4. **Two cue markers** — the icon's playhead motif: a thin **indigo** (`rgb(0.42, 0.40, 0.93)`) vertical line with a filled round dot cap on top, standing on the waveform at two positions.
5. **Precise straight arrow** — icon → folder, thin (`1.8 pt`) light-grey `rgb(0.88, 0.86, 0.80)` @ 0.92 alpha, a sharp triangular head, and a small filled **origin node** dot at the start for a measured, technical read (the "engineering feel" the user asked for — explicitly NOT hand-drawn).

**Layout anchors (art coordinate space, origin top-left, 600 × 400):**

- App-icon center `(168, 165)`, Applications-folder center `(432, 165)`, live icon size **112**.
- Waveform strip: centered on x = 300, half-width **205**, baseline y = **305**, bar max half-height **22**, bar width **1.7**, pitch **5**. Edge fade over the outer 6% of the strip width.
- Cue markers at x = `300 − 72` and `300 + 58`; each line spans baseline `−22 … +42`, dot radius 4.5 at the top.
- Arrow from `(168 + 76, 165)` to `(432 − 76, 165)`.

**Deterministic waveform height** for bar `i` at normalized position `t ∈ [0,1]`:

```
macro    = clamp(0.42 + 0.30·sin(8.2t + 0.4) + 0.16·sin(19.0t + 2.1) + 0.10·sin(3.1t + 1.0), 0.06, 1)
edge     = clamp(min(t, 1−t) / 0.06, 0, 1)
detail   = 0.30 + 0.70·hash01(i)
transient= hash01(13i + 7) > 0.90 ? 1.4 : 1.0
h        = max(1.2, 22 · macro · detail · transient · edge)
```

where `hash01(n)` is a fixed integer hash → `[0,1)` (splitmix-style: `x = n·2654435761 + 12345; x ^= x>>33; x *= 0xff51afd7ed558ccd; x ^= x>>33; return (x % 100000)/100000`). No unseeded randomness anywhere — the art is a pure function of the constants.

## Components / architecture

Two units, each with one clear job:

1. **`scripts/generate-dmg-background.swift`** (new) — a standalone `#!/usr/bin/env swift` CoreGraphics program, mirroring `generate-app-icon.swift`. Renders **only the background art** (layers 1–5 above — no live icons, labels, or title bar) and writes two committed PNGs:
   - `scripts/dmg-assets/dmg-background.png` — 600 × 400 (1×)
   - `scripts/dmg-assets/dmg-background@2x.png` — 1200 × 800 (2×, retina)

   Run from repo root: `./scripts/generate-dmg-background.swift`. Deterministic; re-running overwrites with identical bytes.

2. **`scripts/make-dmg.sh`** (edit) — wire the background in and re-anchor the layout:
   - `--window-size 600 400`
   - `--background scripts/dmg-assets/dmg-background.png` (create-dmg picks up the `@2x` sibling for retina; the exact retina mechanism — 2× sibling vs. embedded 144 DPI — is finalized in the plan and verified by mounting on a retina display)
   - `--icon-size 112`
   - `--icon "OnlyCue.app" 168 165` and `--app-drop-link 432 165` (Finder icon coordinates calibrated to the art anchors; verified by mounting and eyeballing alignment — Finder's coordinate origin/rounding is confirmed empirically, not assumed)
   - keep `--hide-extension`, `--no-internet-enable`, volname, signed/unsigned modes unchanged.

The `@2x` naming and the `dmg-assets/` location are the interface between the two units; nothing else couples them.

## Testing / verification

This is build-time raster artwork, so verification is dimensional + visual, not behavioral unit tests:

- **Deterministic output:** running `generate-dmg-background.swift` twice produces byte-identical files (guards the "committed art, reproducible" contract).
- **Dimensions:** outputs are exactly 600×400 and 1200×800.
- **End-to-end:** `RELEASE_MODE=unsigned scripts/build-release.sh && scripts/make-dmg.sh` succeeds; mount the produced `.dmg`, screenshot the volume window, and confirm (a) the branded background renders, (b) the app icon sits in the glow and the folder on the right, arrow between them, (c) crisp on retina. Attach the mounted-window screenshot for review (a real screenshot of the real installer, per the repo's screenshot rule).

No `ProjectModel`, schema, or app runtime code is touched; there is no app-behavior surface to regress.

## Out of scope

- Signed/notarized DMG changes (the existing `signed` mode still works; artwork is mode-independent).
- Changing the app icon itself.
- Localizing the installer (volume name / labels are Finder-drawn and unchanged).

- Reference: `scripts/generate-app-icon.swift` (convention), `OnlyCue/Resources/Assets.xcassets/AppIcon.appiconset/` (icon motif)
