# Windows M1 — Contract-First Design

**Epic:** #728 · **Parent spec:** `docs/superpowers/specs/2026-08-08-windows-port-design.md`
**Status:** proposed · **Date:** 2026-09-14

Settles how M1 is built now that D1/D2 are decided:

- **D1 = contract-first.** Golden vectors are extended across every M1 domain,
  `OnlyCue.Core` is implemented against them, and WinUI comes last.
- **D2 = thin XAML + CI build.** Logic lives in `OnlyCue.Core` (vector-locked) and
  `OnlyCue.App.ViewModels` (a plain `net10.0` library, unit-tested on macOS).
  `OnlyCue.App` XAML is binding-only and is **built, never run**, in CI.

## Goal

Every behaviour a Windows user depends on in M1 is pinned by a committed JSON
vector that macOS generates and Windows CI verifies — so that a Mac-only agent can
build the Windows core with real confidence, not assumption.

## Two findings that change the parent spec

### 1. `.cuelist` is encrypted — the parent spec does not mention this

`OnlyCue/Document/CuelistCrypto.swift` seals every document in an **AES-256-GCM**
envelope: `"OCUE"` magic (4B) ‖ version `0x01` (1B) ‖ nonce (12B) ‖ ciphertext ‖
tag (16B), under a 32-byte key compiled into the binary. A file lacking the magic
is passed through as legacy plaintext. The `.occues` interchange file uses the same
scheme with `"OCCU"` magic and **no** legacy passthrough.

Consequences:

- C# must reimplement the envelope (`System.Security.Cryptography.AesGcm`) or
  Windows cannot open a single real document. This is M1 scope and was invisible in
  the parent spec.
- The key being extractable is **already accepted** — ADR-021. Shipping it in a
  second binary changes nothing about the threat model. No new decision needed.
- **`seal` cannot be vector-pinned**: AES-GCM draws a fresh random nonce, so its
  output is non-deterministic by design. The vector pins `open` over fixed bytes;
  `seal` is covered by a C#-side round-trip property test instead.

### 2. The schema is v23 with a 23-rung ladder, and MA2 export is four artifacts

The parent spec says v19. Reality (`ProjectModel.swift:5`): **v23**, with v1–v7
migrated inline in `ProjectModel+Migration.swift` and v8–v22 in their own files.
Every rung must be walked, because a v1 file must still open on Windows.

MA2 export is not "lua" alone — it is `MA2SequenceXMLGenerator.xml`,
`MA2TimecodeXMLGenerator.xml`, `MA2PluginGenerator.lua`, and
`MA2PluginGenerator.manifestXML`. All four are pure string producers.

## The seven vector files

Each is generated by an `OnlyCueTests` XCTest following the existing
`TimecodeGoldenVectorTests` pattern: **bootstrap-and-fail if the file is missing,
byte-compare otherwise.** Each is verified by an xUnit test in
`OnlyCue.Core.Tests`.

| # | File | Swift source of truth | Pins |
|---|---|---|---|
| 1 | `golden/cuelist-envelope-v1.json` | `CuelistCrypto` | `open` over fixed envelopes: valid OCUE, valid OCCU, legacy plaintext passthrough, bad magic, bad version, truncated, tampered tag |
| 2 | `golden/cuelist-migration-v1.json` | `ProjectModel.decode` | one representative document per schema version 1…23 → the canonical v23 model |
| 3 | `golden/cue-numbering-v1.json` | `CueNumberAssignment.next`, `CueNumberAutoFill.assignments` | insertion numbering + auto-fill, incl. the 0.1-step and thousandth-subdivision fallbacks |
| 4 | `golden/ma2-telnet-v1.json` | `MA2CommandPlanner.commands`, `MA2TrigTime`, `MA2CueNumber`, `MA2Name.sanitize` | the emitted telnet command list |
| 5 | `golden/ma2-export-v1.json` | the four generators above | sequence XML, timecode XML, plugin lua, manifest XML |
| 6 | `golden/osc-v1.json` | `OSCParser.parse`, `OSCCommand.from` | base64 datagram → parsed message → mapped command, incl. bundles and malformed input |
| 7 | `golden/tempo-grid-v1.json` | `DerivedTempoGrid` | segments, `beatTimes`, `barTimes`, `nearestBeat`, `nearestBar` |

### Encoding rules (apply to all seven)

- `JSONEncoder` with `.prettyPrinted, .sortedKeys, .withoutEscapingSlashes` — same
  as `timecode-v1.json`, so diffs stay reviewable.
- **Doubles are emitted as round-trip-exact decimal strings**, not JSON numbers.
  Swift's and .NET's shortest-representation formatters do not agree in every case;
  comparing formatted text would produce false drift. Both sides parse the string
  to an IEEE-754 `double` and compare bitwise.
- Binary payloads (OSC datagrams, crypto envelopes) are **base64** strings.
- Any generator taking a timestamp (`datetime:`) is fed a **fixed literal**, never
  `Date()`.

## Delivery — three issues, three PRs

Grouped so each PR is reviewable on its own and each lands a working slice of
`OnlyCue.Core`.

1. **M1a — document layer.** Vectors 1 + 2. `OnlyCue.Core`: envelope codec,
   `ProjectModel` DTOs, the full migration ladder. Riskiest and largest; goes first
   because everything else consumes the model.
2. **M1b — planning logic.** Vectors 3 + 7. Cue numbering and the tempo grid. Both
   are already pure Swift with no platform dependency — a near-mechanical port.
3. **M1c — show control.** Vectors 4 + 5 + 6. MA2 telnet planning, the four export
   artifacts, OSC parse+map. Pure string/byte work; the telnet socket and the UDP
   listener are **not** in this slice.

Each PR carries: the Swift generator test, the committed vector, the C#
implementation, and the xUnit verifier. CI job *"Golden vectors (Windows, C# core)"*
must be green.

After M1c, `OnlyCue.App.ViewModels` and the WinUI shell follow as separate work
under the D2 split.

## Explicitly out of scope for M1

Audio playback and any audio hardware; waveform generation; video; LTC/MTC; MIDI;
the MA2 telnet socket and FTP upload; the OSC UDP listener; in-app update.

## Acceptance

- All seven vectors committed and byte-stable across repeat runs on macOS.
- `dotnet test` green on `windows-latest` for every vector.
- Deleting a vector file and re-running the Swift suite regenerates it **and
  fails**, so a contract change is always reviewed.
- A real `.cuelist` saved by macOS v0.32 opens in the C# core and round-trips to
  byte-identical plaintext JSON.

## Risks

- **Migration-ladder fidelity.** 23 rungs re-implemented by hand is where silent
  divergence is most likely. Mitigated by vector 2 covering *every* rung, not just
  the newest.
- **Double formatting.** Addressed by the round-trip-exact string rule above; if it
  still drifts, the fallback is to compare only to a fixed epsilon and to say so in
  the vector.
- **XML/lua whitespace.** The generators are compared byte-for-byte, so C# must
  match indentation and line endings exactly (`\n`, not `\r\n`) — worth calling out
  in review since .NET defaults differ on Windows.
